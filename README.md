# 気仙沼星空観望会 予約システム 仕様書

## 📖 概要

気仙沼星空観望会のワークショップ予約システムです。参加者が基本情報を入力し、ワークショップの部を選択して予約できるWebアプリケーションです。

### 🎯 主要機能
- マルチステップフォームによる直感的な予約プロセス
- リアルタイムのメールアドレスバリデーション
- ワークショップ参加人数に応じた部の選択
- レスポンシブデザイン（モバイル・タブレット・PC対応）
- Google Apps Script APIとの連携

### 🌐 デプロイ形式
- **GitHub Pages**: 静的サイトホスティング
- **Google Apps Script**: バックエンド API

## 🏗️ システム構成

### ファイル構成
```
├── index.html          # メインHTML（エントリーポイント）
├── styles.css          # CSSスタイルシート
├── script.js           # JavaScript機能
├── iframe-embed-codes.html  # 埋め込み用コード集
├── README.md           # 本仕様書
└── Code.gs             # Google Apps Script バックエンド
```

- **バックエンド**: Google Apps Script

## 📋 機能仕様

### 1. ユーザーインターフェース

#### 1.1 ステップインジケーター
- 4段階のプロセス表示
- 現在のステップをビジュアル化
- 完了済みステップの識別

#### 1.2 フォームステップ

**ステップ1: 基本情報**
- 代表者氏名（必須、文字列）
- 来場地域（必須、選択式）
  - 気仙沼市内
  - 宮城県内（気仙沼市以外）
  - 岩手県
  - 福島県
  - その他東北地方
  - 関東地方
  - その他
- メールアドレス（必須、email形式）
- ワークショップ参加（必須、選択式）
  - 参加する
  - 参加しない（観望会のみ）

**ステップ2: ワークショップ詳細**（ワークショップ参加者のみ）
- ワークショップ参加人数（必須、1-5人）
- 予約する部（必須、動的選択肢）

**ステップ3: 確認・登録**
- 入力内容の表示確認
- 登録ボタン

**ステップ4: 完了**
- 完了メッセージ
- 新規予約作成ボタン

### 2. バリデーション機能

#### 2.1 リアルタイムバリデーション
- メールアドレス形式チェック
- 入力中の視覚的フィードバック
- エラー・成功メッセージの表示

#### 2.2 送信前バリデーション
- 必須項目の入力確認
- データ形式の検証
- 部の空席状況確認

### 3. API連携

#### 3.1 部情報取得
- **エンドポイント**: `${API_URL}?action=getParts`
- **メソッド**: GET
- **レスポンス**: 
```json
{
  "success": true,
  "parts": [
    {
      "name": "第1部 (19:00-20:00)",
      "capacity": 20,
      "remaining": 15
    }
  ]
}
```

#### 3.2 予約登録
- **エンドポイント**: `${API_URL}`
- **メソッド**: POST
- **データ**: FormData形式
- **フィールド**:
  - 代表者氏名
  - 来場地域
  - メールアドレス
  - ワークショップ参加
  - ワークショップ参加人数（条件付き）
  - 予約する部（条件付き）

### 4. レスポンシブデザイン

#### 4.1 ブレイクポイント
- **モバイル**: ~480px
- **タブレット**: 481px~768px
- **デスクトップ**: 769px~

#### 4.2 適応的調整
- フォントサイズの自動調整
- レイアウトの最適化
- タッチインターフェース対応

## 📊 データフロー

### 1. ページ読み込み
```
ユーザーアクセス → DOM初期化 → UI要素初期化 → イベントリスナー設定
```

### 2. フォーム入力
```
入力 → バリデーション → 状態更新 → UI反映
```

### 3. ステップ進行
```
次へボタン → バリデーション → データ保存 → ステップ更新 → UI更新
```

### 4. 予約送信
```
送信ボタン → 最終バリデーション → API送信 → レスポンス処理 → 完了画面
```
